# 音乐唱片与生物舞蹈：使用及学习说明

## 当前已经接入什么

- 唱片 ID：`examplemod:dance_disc`，中文名称“音乐唱片 · 舞动”。
- 音乐来自你提供的 `src/main/resources/朋友的酒.mp4`，没有改动原文件。
- 游戏使用转换后的单声道 OGG Vorbis，48 kHz，时长 **183.83275 秒**（约 3 分 4 秒）。
- 曲名为“朋友的酒”；播放提示和唱片说明显示“小助 — 朋友的酒”。这是音乐署名，Mod 作者仍为 `xc`。
- 舞蹈速度暂设 **120 BPM**。这只是手动默认值，不是对歌曲节拍的自动测量。
- 播放此唱片时，以唱片机为中心、默认半径 **8 格**内的普通生物出现弹簧式竖直伸缩并持续自转：高度在原高的 **45%～155%** 间往复，一拍伸缩一次、四拍旋转一周；脚底固定，不再后仰、侧摆或整体弹跳。
- 吸引范围按最新要求固定为 **32 格球形半径**，音乐本身的传播距离不变：可寻路生物会主动走向唱片机，靠近后停在约 2.5 格内，进入 8 格后同时跳舞。吸引通过正常寻路实现，不穿墙、不瞬移。
- 取出唱片、破坏唱片机、播放自然结束后，舞蹈与吸引都停止；多台唱片机独立跟踪，重叠范围内优先跟随最近的一台。

**表现范围：**动作按“像弹簧一样上下拉长缩短，同时自转”的要求实现，不是坐姿、手臂和腿部骨骼动画。猪、牛、僵尸等骨骼不同，统一使用模型变换；舞蹈渲染本身不改变碰撞箱；新增吸引会临时接管闲逛/看向目标，让生物正常寻路靠近，停止后归还控制。逃命、浮水等更高优先级行为仍优先，有战斗目标的生物不会被吸引。睡眠、骑乘/被骑乘、死亡的生物及末影龙、凋灵不参与；使用特殊自定义渲染器的其他 Mod 生物不保证支持。吸引还会跳过 NoAI 生物、被拴绳牵住的生物和被命令坐下的宠物；只对使用原版 PathfinderMob 导航体系的生物生效，无路可走时不会强制拖拽。

## 1. 在游戏里测试

1. 完全关闭之前运行的开发游戏，再通过 IDEA 的 `runClient` 配置或 Gradle 的 `runClient` 任务启动。音轨时长在注册唱片时读取，单按 F3+T 不能更新它。
2. 新建一个允许作弊的创造模式测试世界。
3. 输入：

   ```mcfunction
   /give @s examplemod:dance_disc
   /give @s minecraft:jukebox
   /give @s minecraft:pig_spawn_egg
   /give @s minecraft:cow_spawn_egg
   ```

4. 放置唱片机，在平坦开阔处、距离唱片机约 10–15 格生成猪和牛，手持新唱片右键唱片机。
5. 检查歌曲是否播放、生物是否主动走近，进入 8 格后是否像弹簧一样竖直伸缩并自转。32 格以外的生物不应主动靠近；8–32 格内会靠近，但暂时不跳舞。可在开阔平地放一只 30 格外的猪验证远距离实际行走。吸引目标通常在约 1 秒内开始，优先级更高的行为可能暂时阻止它。
6. 在生物走近途中再次右键取出唱片，确认声音、舞蹈和吸引停止。原版闲逛恢复后仍可能自行走动，不是让它永久定身。还可以分别测试破坏唱片机、等待歌曲结束、两台唱片机只关闭其中一台。
7. 原版唱片不会触发本 Mod 的舞蹈。声音听不见时，检查“音乐和声音”中的**唱片机/音符盒**音量以及主音量。

原版唱片机没有通用的“红石暂停开关”。这里的“关闭”指取出唱片、破坏唱片机或自然播完；并未新增开关方块或暂停按钮。自然播完时遵循原版唱片机的约 1 秒尾部缓冲。

## 2. 这次做了哪几步

1. 注册 `SoundEvent` 和 `RecordItem`，并把唱片加入创造模式分页。
2. 用临时放在 `build/tooling` 的免安装 FFmpeg 从 MP4 提取音频，转成单声道 OGG Vorbis，避免立体声造成空间衰减异常。
3. 添加声音映射 `sounds.json`（`stream: true`）、唱片物品模型、32×32 PNG 贴图、语言文本与 `minecraft:music_discs` 标签。
4. 添加导入工具：校验 OGG 容器、读取采样率和时长，更新资源与曲目信息，不修改原文件。
5. 服务端监听唱片机的原版游戏事件，并逐 tick 检查是否仍在播放；把附近有效唱片机状态发给客户端。
6. 客户端在生物渲染事件中临时改变模型矩阵；结束时恢复，不把动作写进生物 NBT。
7. 给服务端可寻路生物挂载 `MusicAttractionGoal`，优先级为 2，临时管理移动和看向目标；最近唱片机停止后可以选择另一台仍在范围内播放的唱片机。
8. 添加自动化测试、音乐完整解码检查，并排除原 MP4 的打包，最终 Mod 只需要 OGG。

所以**这次既修改了 Java，也增加了资源文件和辅助工具**，并非仅添加贴图。

## 4. 如何换音乐、作者或节奏

如果已经有**单声道 OGG Vorbis**，在项目根目录打开终端：

```powershell
node tools/import-music.cjs "D:\你的音乐\新曲子.ogg" --title "曲名" --artist "作者名" --bpm 120
```

当前曲子只想改作者/BPM，也可以把已有的 `src/main/resources/assets/examplemod/sounds/records/dance_song.ogg` 作为输入，工具会先完整读取后再写入。

若输入是 MP4/MP3/WAV，应先用 Audacity 导出 **OGG Vorbis / 单声道**，或者使用已下载的临时 FFmpeg：

```powershell
& ".\build\tooling\imageio-ffmpeg\imageio_ffmpeg\binaries\ffmpeg-win-x86_64-v7.1.exe" -i "D:\你的音乐\歌曲.mp4" -map 0:a:0 -vn -ac 1 -ar 48000 -c:a libvorbis -q:a 5 -n ".\build\歌曲.ogg"
node tools/import-music.cjs ".\build\歌曲.ogg" --title "曲名" --artist "作者名" --bpm 120
```

`-n` 表示不覆盖已存在的输出，请换一个输出文件名。`build` 是临时目录，执行 Gradle `clean` 会清除临时转换工具，**但不会删除已经导入到源代码资源目录的 OGG 和原 MP4**。更换音乐后重启游戏并重新插入唱片；仅改后缀不能把 MP4 转成 OGG。

时长由导入工具自动计算，不要把秒数直接传给 Forge 的 Supplier 版 `RecordItem` 构造方法。本项目自动换算为 `ceil(秒数 × 20)`。

## 5. 舞蹈与吸引范围

舞蹈半径仍可在世界的 `serverconfig/examplemod-dance-server.toml` 中修改：

```toml
danceRadius = 8.0
```

单人开发世界一般在 `run/saves/<世界名>/serverconfig/`；专用服务器在相应世界目录的 `serverconfig/`。舞蹈范围允许 1–64 格。建议关闭世界后修改再重新进入。

吸引半径按最新要求固定为 **32 格**，由 `MusicAttractionGoal.ATTRACTION_RADIUS` 管理，不再使用旧世界的 `attractionRadius` 配置。到达或超出 32 格边界时不再吸引；只影响已经加载、正在运行 AI 且有可达路线的生物，不强制加载区块、不隔墙拉扯。单次寻路使用专门的搜索距离，不修改动物默认的追踪属性。

旧存档的 `attractionRadius = 16.0` 已不再参与逻辑；Forge 加载时会修正旧配置，无需删除世界。声音仍保持原版唱片机的传播规则：音量 4 × 衰减基距 16 = 64 格，**本次只把吸引改为 32 格，不缩短音乐传播距离**。个人音量滑块或静音不改变服务端吸引范围。

伸缩幅度和自转速度见 `DanceMotion.java`：`0.55` 控制高度变化幅度，`beats * 90` 表示每拍转 90 度。120 BPM 时每 0.5 秒伸缩一轮，每 2 秒自转一周。只修改渲染矩阵，不修改碰撞箱或真实身高。

## 6. 自动化验证与限制

- Node 导入工具与当前资源：9 项测试，包括无效文件、单声道、时长、BPM、文件完整性和实际写出的 JSON。
- 舞蹈数学测试：30,000 组采样，验证伸缩峰谷、正常初始高度、自转周期及循环连续性。
- 原有 Forge GameTest：5 项唱片状态测试。
- 11 项吸引 GameTest：真实走近和取出停止、32 格球形吸引边界、最近唱片机切换、破坏停止、自然结束停止、原版唱片不吸引、NoAI/坐下/战斗/骑乘保护、抵达停留并恢复原 AI、墙体阻挡、30 格远距离真实寻路且不修改追踪属性、离开吸引范围后停止。每项独立分批，防止测试用唱片机互相干扰。
- 音频已通过 FFmpeg 完整解码检查。
- 服务端 GameTest 不会打开客户端窗口，不能证明画面动作与声音的主观效果；仍需按第 1 节实际试玩。

运行导入工具测试：`node --test tests/music-import.test.cjs`。

当前机器的普通 Gradle 命令仍遇到 Forge Maven 证书预检查失败。验证时用 Java 17、本机 `D:\maven-repository` 缓存及 **`--offline`** 模式，仅在该次进程跳过预检查，没有把关闭证书检查写入项目配置，也没有修复证书根因：

```powershell
$env:JAVA_HOME = 'D:\Java\jdk-17.0.12'
.\gradlew.bat --gradle-user-home D:\maven-repository --offline '-Dnet.minecraftforge.gradle.check.certs=false' build runGameTestServer
```

需要启动客户端而证书问题仍未解决时，可以在同样的**离线缓存条件**下将最后的任务改为 `runClient`。不要把跳过检查作为联网下载依赖时的长期解决方案；后续应检查 Java 信任库、系统时间及代理证书。
